## 6. Local-first and sync
- The phone is the boss: every change is saved in Dexie FIRST with `pending_sync = 1`; the engine sends it later. Client-generated UUIDs; upsert by id so sending twice is harmless; audit and stock_moves use ignore-duplicates (add-only). Nothing is ever deleted.
- Each create/edit/cancel writes its audit row in the SAME Dexie transaction. Anything touching money and stock/several tables is ONE transaction. **Dexie rule: the function given to db.transaction MUST be written with the `async` keyword itself, otherwise PrematureCommitError.**
- Push order: shops, parties, entries, audit_log, then optional groups (stock: products + stock_moves; cash: cash_closings). A refused row is parked "blocked" (shown in Settings), the rest still go. Offline failures retry (timer with back-off, `online` event, app returning to screen). A row that changed while travelling stays pending.
- Pull: at start, every 45 s while visible and 5 min hidden, plus "Abhi taaza karo". A pending local change is never overwritten. Cancelled is final. Pull BEFORE push when a party/product is pending, and always pull after push, so a two-phone clash is noticed: this phone's change is kept AND the other version is written down (conflicts.ts; Settings "Do phone se alag badlav" with "Dekh liya"). Entries, stock moves and closings are frozen/add-only so they cannot clash.
- New phone, same Google login: stage 'restoring' asks the server BEFORE asking for a shop name; brings back shop, customers, entries, diary, stock, closings. If two phones each made a shop before syncing, the server's shop wins and local data moves into it.
- Derived data kept per phone and always rebuildable: `party_stats` {balance, last_at} and `product_stats`, updated in the same transaction as each change; `statsRepo.verify/rebuildAll`, `productsRepo.verify/rebuildStats`; verified after any pull that brought rows (a wrong summary is rebuilt and reported).
- Clock check: pull asks server_time(); a difference over 10 minutes shows ClockBanner.
- UI: SyncBadge on Home ("Save ho gaya" / "Internet aate hi save hoga" / "Save ho raha hai..." / problem); ConnectionBar at the top of every screen only when offline (with pending count) or the server refused something; Settings "Abhi save karo".
- Fake server for tests (fakeRemote.ts) must obey the REAL database rules.
- Big khata rules: Home reads only customers + summaries + 5 newest entries + today's entries (index ranges); lists draw 60 at a time with "Aur dikhao" (`useLimit`); search uses a prepared index. NEVER read all entries in a screen. Measured: a Dexie `.filter()` on a big range is about 10x slower than `toArray()` then `Array.filter`; stock moves are read by a table scan + filter (src/data/moves.ts). Target: month report under 1 s at 6x slower CPU with 20,000 sales.
- Testing mode (Settings > Testing): flag `hv_testing`; separate Dexie DB `hisabview_testing`, sync is a do-nothing object, a test shop is made at once, a TestBanner turns it off. DB chosen once at start so each switch reloads.

## 10. Business rules by module
**WhatsApp**: src/lib/whatsapp.ts makes wa.me links (Pakistani numbers to 92...); on Android open `whatsapp://send` directly, fall back to wa.me after 1.5 s; nothing is sent until the shopkeeper presses send. Message words in translations (msg*, bal*, tone*), follow app language, no accounting words. Statement text keeps the newest lines that fit 2,400 link characters with an "earlier balance" line.
**Today (/today)**: every entry of the Pakistan day; tap = cancel/Badlo; WhatsApp summary; buttons Sale / Kharcha; sale and kharcha never change customer balances or Lene/Dene totals.
**Stock (migration 0006)**: stock = SUM of add-only `stock_moves` (opening, purchase, purchase_return, sale, adjust, damaged, lost, reversal); a mistake or cancelled sale is undone by a 'reversal' pointing at the move (one reversal per move). Quantities are WHOLE numbers of the base unit (piece, gram, ml); dozen/kg/litre built in; shopkeeper adds packings ("1 carton = 144 piece"); typed quantity -> base units by digits, never floats; half a piece refused; line total = round(base qty x unit price / unit factor) rounded once; valuation = stock x cost price rounded once. One Dexie transaction for sale (cash_sale, or Diye on udhaar), purchase (entry on supplier account + part-paid linked 'diye'), purchase return (+ linked 'mile'). Newest purchase price becomes cost_price (audited), but a Rs 0 line NEVER changes it. Selling more than stock = one warning, second tap saves. Cancel puts stock back and cancels linked payment. Bill number (invoice_no) warns once if the same supplier already has it. Screens: StockScreen (list, value at cost, low filter, hidden items), ProductFormScreen, ProductScreen (history, "Stock theek karo", supplier rates, "Kharid ke rate" filter), TradeScreen (buy/sell/return: items -> details -> check -> Theek hai). **New item form (important)**: ONLY the name is required. Sell price is shown but optional. Product photo shrunk to a small JPEG (max 256 px, under 60,000 characters).

**Cashbook (0007)**: money in = cash sale, mile (customer or supplier refund), deposit; money out = diye to a SUPPLIER, kharcha, withdrawal. Screens: /cashbook (day arrows, in/out lines, by method, withdraw/deposit, "Din band karo"), /cashbook/close (keypad, live difference, note), /expenses (Aaj / Is mahine, per category).
